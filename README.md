# rdp-cert-fix

Чинит RDP на Windows, где КриптоПро CSP ломает самоподписанный TLS-сертификат службы удалённых рабочих столов.

**Симптом:** RDP сбрасывает любое подключение сразу после рукопожатия (клиент пишет «внутренняя ошибка» или просто отваливается). В журнале System:
- `TerminalServices-RemoteConnectionManager` 1057 - «не удалось создать новый самозаверяющий сертификат… Указан неправильный алгоритм»;
- `Schannel` 36870 - ошибка доступа к закрытому ключу, код `0x8009030D`.

## Что делает

1. Останавливает `UmRdpService` и `TermService`.
2. Удаляет сертификаты из `LocalMachine\Remote Desktop` и ранее выпущенные этой утилитой сертификаты из `LocalMachine\My` вместе с их ключами.
3. Выпускает самоподписанный сертификат `CN=<имя ПК>`: RSA-2048, SHA-256, EKU Server Authentication, срок 10 лет. Ключ создаётся в Microsoft Software Key Storage Provider (в обход КриптоПро), NETWORK SERVICE получает чтение ключа.
4. Записывает отпечаток в `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp\SSLCertificateSHA1Hash`.
5. Запускает службы и проверяет, что RDP на `127.0.0.1` отвечает на X.224-рукопожатие.

Запускать от администратора (манифест сам запросит UAC). `/quiet` - не ждать Enter в конце. Код возврата: 0 - всё ок, 2 - есть предупреждения, 1 - ошибка.

Активные RDP-сеансы при перезапуске службы отключатся, к ним можно переподключиться.

После запуска в журнале может остаться событие 1057 при старте службы: TermService всё равно пытается сделать свой сертификат, но использует привязанный. Это не мешает.

## Сборка

Нужна Visual Studio с C++. Запустить `build.bat`, получится `rdp-cert-fix.exe` (x64, статический CRT, без зависимостей).
